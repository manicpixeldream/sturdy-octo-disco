# v0.10 — Team Chat

> Historical milestone notes. See the [current README](../README.md) for current behavior, including browser persistence and Firebase team workspaces.

## Implemented

Team now has an Open team chat entry point. `/team/chat` contains one local demo
channel for the active case, using the existing workspace shell, typography,
colors, borders, avatars and controls. There are no invented teammates, automated
replies, online indicators or read receipts.

Messages show the actual sender, local date/time, body text and explicit linked
references. The composer supports multiline text, Ctrl+Enter/Cmd+Enter to send,
and up to five task/exhibit links from a searchable picker. A reference-only
message is permitted. Selected references can be removed before sending. Typed
names remain ordinary text rather than ambiguous auto-generated links.

Task links open `/team/task/:id`, showing the current task, assignee and completion
or due status. Own tasks offer a route to Profile's checklist; other teammates'
tasks remain read-only. This lets every team-task mention open its actual item
without routing incorrectly to the current user's personal checklist. Missing
references have an honest unavailable state and a working back route.

Exhibit links open the existing Research source reader. Chat links do not create
brief or examination citations, and do not change admission status or source case
materials. Newly assigned role-responsibility tasks become available in the picker
through the shared TaskController.

## Reliability and data

ChatMessage and ChatMention are immutable values with equality and map/JSON
serialization. ChatRepository isolates persistence behind an interface;
MockChatRepository stores messages for the current app session and separates
channels by case. Sending the same ID and payload is idempotent; a conflicting
payload for an existing ID is rejected without replacing the message.

ChatController validates sends, resolves references to current canonical labels,
prevents concurrent sends, handles loading errors and retry, and uses a 20-second
send timeout. A failed send does not append an apparently delivered message.
Unchanged retries reuse the same ID, payload and timestamp. Successful sends clear
the composer; failed sends retain its text and selected references. Results from
disposed controllers or old active cases cannot enter the current channel.

History is retained across controller reloads and navigation in the current app
session. The view scrolls to the latest own message without automatically pulling
a reader away from older history for another sender's message. The composer stays
above the keyboard; compact layouts use an accessible attachment icon to avoid
crowding Send. Long task/exhibit labels wrap inside reference buttons.

## Limits

- Messages are local demo data. No real teammate receives a message, and there is
  no live backend, notification service or cross-device synchronization.
- Reloading/restarting resets messages and drafts. Leaving a route that disposes
  its composer can discard an unsent draft; this is not persistent draft storage.
- There is one active-case channel, not direct messaging, multiple channels,
  message editing/deletion or attendance tracking.
- Task detail is a reference view; personal completion remains in Profile.

No dependencies, fonts, palette changes or underlying case-material edits were
introduced. Existing v0.9 work remains intact.

once to initialize the new chat provider and remains available for hot reload.

## Developer manual checks

1. Open Team → Open team chat. Send a message, then send using Ctrl+Enter or
   Cmd+Enter; confirm each appears once and the successful draft clears.
2. Link a teammate's task and an exhibit. Open each reference and verify its
   actual title, assignee/source details and back navigation.
3. Search the picker, select five references, remove one and send links without
   text. Confirm the limit and selected references remain clear.
4. Check mobile/tablet/desktop widths, enlarged text, keyboard access and Midnight.
   Ensure the composer and Send remain usable with the keyboard open.
5. Switch tabs and return to chat, then reload to confirm the disclosed local
   session reset. No real messages or notifications should be expected.

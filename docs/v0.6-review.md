# v0.6 · Research hub and review follow-up

## Implemented

Research now has Ask and Library modes in the current editorial design system,
with a dark Research surface and paper-like source reader. Ask provides prepared,
keyword-matched responses with numbered points, source citations, loading, error,
retry, and timeout behavior. The composer stays at the bottom of the available
page area and above the keyboard. Suggestion buttons submit their visible text.

Library saves sources for the app session and groups them under Precedents,
Definitions, Articles, and Case materials. The catalogue contains three reference
summaries plus the unchanged 14 exhibit descriptions and six affidavits. Users
can browse, search, save, and unsave. Reloading clears chat and saved items; the
interface discloses that limit.

The source reader includes the citation, scope/provenance, original sample packet
text or a short reference summary, an official-address copy action for external
references, and a live “Cited in” list. Actual brief evidence references and
Research answers are indexed. Usage links open the relevant brief fact or answer.
The citation API also accepts examination-question usages for v0.9; no fictional
exam scripts or usage entries were added. Saving a source never invents a usage.

Unknown or duplicate source references in a service response are rejected rather
than rendering an apparently sourced claim. Replies from disposed controllers or
an old case are ignored. Catalogue errors and response errors can be retried
separately; retrying a failed response keeps the original question once.

## Reference provenance

Reference summaries are training material, not an assertion that federal rules
or the cited precedent govern the fictional state case. The UI identifies the
scope and historical date of each item. The reference text was checked against:

- [Daubert, 509 U.S. 579 (1993), official U.S. Reports PDF](https://www.govinfo.gov/content/pkg/USREPORTS-509/pdf/USREPORTS-509-579.pdf).
- [Federal Rules of Evidence, December 1, 2024 compilation, Rule 401](https://www.uscourts.gov/sites/default/files/2025-02/federal-rules-of-evidence-dec-1-2024_0.pdf).
- [Beth Schuster, “Police Lineups: Making Eyewitness Identification More Reliable,” NIJ, October 1, 2007](https://nij.ojp.gov/topics/articles/police-lineups-making-eyewitness-identification-more-reliable).

No runtime web research, LLM calls, accounts, or cross-device persistence are
claimed. These remain behind future service implementations in the plan.

## Manual browser smoke test

Validation passed locally on Flutter 3.47.2 / Dart 3.13.2:

- `flutter pub get --enforce-lockfile`: succeeds with the committed dependency versions; CI uses the same command.
- `flutter analyze --no-pub`: no issues.
- `flutter test --no-pub`: 117 tests pass.
- `flutter build web --no-pub`: production web build and Wasm dry run succeed.

No new dependencies were added. The original case materials are unchanged.

The repository reserves browser testing for developers in
`.cursor/rules/no-agent-ui-testing.mdc`. No agent-run server or browser was used.
Widget-rendered layout checks cover 320px/390px phones, an 834px tablet, and a
1440px desktop, including larger text, all themes, and keyboard insets.

1. From Home, open Ask the case. Send a suggestion and a typed question; inspect
   the numbered response and its citations.
2. Open a citation, save its source, and find it in Library. Search, switch
   between Saved and All sources, and unsave it.
3. Follow “Cited in” back to a Research answer and a brief fact. Verify the source
   scope labels and use the official-link copy action.
4. Resize the browser, enlarge text, and open the keyboard on a phone. Confirm
   the composer and navigation do not obscure content.

Optional rendered inspection images can be regenerated without a browser:

```sh
flutter test --no-pub test/design/research_layout_test.dart --dart-define=GAVEL_CAPTURE=true
```

The command writes PNGs to `/private/tmp/gavel-v06`; normal tests do not write
inspection images.

# v0.7 — Team and Assign Role

## Implemented

Team uses the existing workspace shell, themes, spacing, cards, status pills,
stat tiles, avatars, tags and progress bars. Wide layouts use WorkspaceColumns;
phone layouts stack the same content. No palette, fonts, navigation style or
package dependencies were added.

The page separates role coverage from preparation completion. Prosecution and Defense each show their attorney roles and a separate witness
group for that side. Opening, closing, direct and cross
attorney responsibilities produce eight attorney slots, for 14 slots in total.
Roster members expand to show their actual preparation tasks.

`/team/assign/:roleId` supports direct linking, recovery from loading errors,
unknown-role messaging, a responsibilities checklist, workload-ranked suggestions,
explicit teammate selection and submission. After assignment it shows the
assignee and prevents duplicate assignment. Filled slots are read-only in this
version; no reassignment or task deletion is implied.

Suggestions are deterministic: fewest unfinished tasks, then name and ID. They
are not live AI or inferred skills. Multiple roles per member are allowed,
including training on both sides. The screen asks users to review scheduling;
it does not claim to enforce competition-specific role restrictions.

## State and repository behavior

Existing teammate and task models/repositories remain in use. New TrialRole and
RoleAssignment models own immutable collections and support serialization,
copyWith and equality. A RoleRepository owns assignments and their responsibility
tasks as one atomic operation. Its in-memory mock rejects unknown members,
unknown roles and already-filled slots before changing state.

RoleController handles loading, failure, retry, disposal and submission guards.
TaskController combines existing preparation tasks with repository-backed role
tasks, deduplicated by ID. Both Home and Team consume that same task state.
Reloading either controller does not duplicate or discard committed role tasks
within the current session. Adding unfinished work can lower completion; filling
a role is never counted as completed preparation.

Assignment responsibility tasks are due on the demo trial date. They are separate
from pre-existing preparation tasks, whose completion is preserved. Task editing
and completion controls remain the v0.8 milestone.

Assignments and their tasks last for the current app session. Browser reloads
reset the mock data. No notification is sent: the action says “Assign {name}”
and both the page and success feedback disclose this. Team chat remains v0.10;
no inactive chat button or fabricated chat message was introduced.

## Verification

- `flutter analyze`: no issues.
- `flutter test`: 130 tests pass, including the existing suite.
- Added tests cover model immutability/serialization, workload ranking,
  repository atomicity, duplicate and invalid assignment rejection, failure and
  retry, concurrent submissions, disposed completion, task/readiness updates,
  Home synchronization, filtering, direct links and unknown roles.
- Widget layout tests cover 320px, 834px and 1440px widths, 1.3x text, and all
  three existing theme variants.

Only Flutter analysis and tests were used for verification. No browser, local
server, production build or native build was run.

## Developer manual checks

1. Open Team; switch Prosecution and Defense. Expand a roster member
   and compare their task queue with the completion summary.
2. Open an unfilled role, review responsibilities and select a teammate. Confirm
   the button uses their name and assigns only when a teammate is selected.
3. Submit once. Confirm the role shows its assignee and the new unfinished tasks
   appear in that member's queue. Compare Home's task total and completion with
   Team; role coverage should increase independently.
4. Visit a filled role and an invalid role deep link. Confirm assignment cannot
   be duplicated and both screens have a usable route back to Team.
5. Check phone/tablet/desktop widths, enlarged text, keyboard focus and Midnight.
   Reload and confirm the disclosed session-only assignment reset.

# v0.9 — Examination Builder

> Historical milestone notes. See the [current README](../README.md) for current behavior, including browser persistence and Firebase team workspaces.

## Implemented

Each witness now has separate Direct and Cross examination scripts at
`/case/witness/:id/exam`, with phase and optional question anchors in the URL.
The affidavit reader exposes both builder entry points. The page preserves the
existing editorial headers, colors, typography, spacing, card shapes and global
navigation. Direct/Cross and the existing Team filter share a reusable segmented
control without changing the Team filter's appearance or keys.

The builder supports:

- Editing a per-script goal.
- Adding and editing question text, estimated seconds, exhibit links and an
  explicit review flag.
- Moving questions up/down with keyboard-accessible buttons.
- Deleting a question with confirmation.
- Drafted, evidence-linked and flagged counts derived from actual questions.
- Prepared suggestions that users explicitly add, flagged for review.
- Loading, empty, unavailable-witness, missing-question and retry states.

Question/goal editors require explicit Save or Cancel actions and remain open
with their draft after a failed save. Saved scripts are changed only after the
repository write succeeds. Reorder/delete failures leave the prior script and
citations unchanged. Save errors are scoped to the affected script rather than
appearing on a different phase. Writes are guarded against concurrent submission,
disposal and completion after an active-case change.

## Timing and examining sides

Questions default to 45 seconds, editable from 1 to 3600 seconds. Estimates
include both the question and the expected answer; they are planning estimates,
not measured rehearsal times.

The timing panel reads the existing packet rule for the selected phase. For
shared rules it totals every saved script for the examining side and phase.
Direct uses the witness's side; cross uses the opposite side. Prosecution direct,
defense direct, prosecution cross and defense cross therefore have independent
budgets. Missing rules are reported as unavailable. The existing per-script rule
flag is respected if a future packet defines a non-shared allowance.

The seeded packet allows 25 minutes for direct and 20 minutes for cross, shared
across witnesses per side. Two 800-second prosecution direct scripts trigger a
26m40s / 25m warning, despite each script fitting individually. The progress bar
clamps at full while the actual total remains visible. No packet timing values
or case materials were modified.

## Exhibit citations

Exhibit chips open the existing Research source reader. Script links are indexed
as real examination-question usages; source “Cited in” entries open the exact
witness, phase and question. The target question is highlighted and scrolled into
view. Editing links updates the index, and removing a link or deleting its
question removes that usage. Reloading Research reconstructs the usages from the
saved script state without duplicates. Brief and Research-answer citations stay
separate.

A preparation reference does not establish that an exhibit was admitted or is
admissible. The UI states this distinction. Only existing active-case exhibits
can be linked; invalid catalogue/script references are rejected.

## Architecture and limits

Immutable ExamQuestion and ExamScript models provide equality, copyWith and map
serialization. ExamRepository stores complete scripts atomically; the in-memory
implementation isolates cases. ExamSuggestionService has a prepared mock
implementation, with timeout/error/retry behavior in ExamController. Controllers
remain Provider/ChangeNotifier-based and routes use go_router.

“Suggest with AI” is explicitly labeled as prepared demo prompts rather than a
live model response. Suggestions do not rewrite or add facts to the case packet,
do not silently become questions, and are flagged for review when added.

All scripts and goals are local to the current application session. Reloading or
restarting resets them. There is no live AI, backend persistence, attendance
tracking, notification delivery, new dependency or change to source case text.

## Developer manual checks

1. In Case → Affidavits, open a witness and choose Build direct examination.
   Edit its goal, add/edit questions, flag one, reorder and delete a question.
2. Link an exhibit, open its source, and follow “Cited in” to the exact question.
   Remove the link and confirm its examination usage disappears.
3. Add enough estimated time across two witnesses on the same side to exceed
   the shared direct budget. Compare the combined warning with each individual
   script, then switch to Cross and confirm the examining side and budget.
4. Request suggestions and explicitly add one. Confirm it is flagged for review
   and Direct/Cross scripts remain separate.
5. Check phone/tablet/desktop widths, enlarged text, keyboard access and Midnight.
   Reload and confirm the disclosed session-only reset.

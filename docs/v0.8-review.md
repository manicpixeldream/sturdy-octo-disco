# v0.8 — Profile checklists and Practice Schedule

## Implemented

Profile replaces its placeholder with the demo teammate's identity, assigned,
complete and remaining task counts, personal progress, and a checkbox checklist.
Only the current teammate's tasks appear. Open tasks are ordered by due date;
completed tasks remain available so completion can be reversed. Task rows use
the existing theme, border colors and corner radii, and provide disabled saving
states and retry controls after a failed write.

A responsive quick-access area opens Practice Schedule, Case, Research, Team and
the existing theme gallery. All routes are real. The design tokens, global
navigation, bundled fonts and existing Team layout are preserved.

Practice Schedule lives at `/me/schedule`. It includes the trial countdown,
Monday–Sunday week strip, previous/next/current week controls, a day filter,
upcoming or ongoing practices, and a weekly practice goal. Session times are
shown in device-local time. The selected week determines the goal total;
selecting a day only changes the session list. Past sessions are omitted from
upcoming results, while an ongoing session remains visible until its end time.

The mock goal is 180 planned minutes per week. It sums the current teammate's
scheduled session durations for the entire selected calendar week, including
earlier sessions, and clamps the progress bar at 100%. The text shows actual
minutes even above the goal. This is a planning measure, not an attendance or
completed-practice claim. Empty selections and repository failures have explicit
states; failed loads can be retried.

## Data and state

The existing TaskRepository now saves completion. Its mock persists updates for
the application session, including role-responsibility tasks. TaskController
merges role tasks with saved records by ID, giving the saved completion record
precedence. Re-fetching task or role data therefore does not reset a completed
responsibility or duplicate its task. Home, Team and Profile consume the same
controller and update together. Role coverage remains separate from preparation
completion.

Writes are not optimistic: failed writes leave the previous checkbox value and
metrics unchanged. Per-task pending guards prevent duplicate submissions;
independent tasks may save concurrently. Disposed controller results are ignored.

PracticeSession is immutable and supports copyWith, equality and map roundtrips.
ScheduleRepository isolates schedule data behind an interface. Its mock creates
four launch-relative practices for demo teammates. ScheduleController owns week
selection, personal filtering, upcoming-session filtering and goal math. Existing
session clock notifications keep time-sensitive page content refreshed.

No dependencies, live services, external messages or changes to case materials
were introduced. Task completion is editable; session creation/editing and
attendance tracking are outside this milestone.

## Limitations

- Task changes, role assignments and schedules remain local to the app session.
  Reloading or restarting resets demo data.
- The profile uses the existing demo teammate rather than an authenticated user.
- Practice dates reset on launch. Sessions are read-only and the weekly goal is
  a fixed demo target.
- No notifications or cross-device synchronization are sent or claimed.

## Manual checks

1. Open Profile, complete and reopen a task. Compare personal counts and the
   team totals on Home and Team.
2. Assign yourself a role in Team, then complete one of its new responsibilities
   from Profile. Switch tabs and confirm the completion remains consistent.
3. Open Practice Schedule from Quick access. Select days, show all week, and
   move between weeks; the goal should follow the week, not the day filter.
4. Check Profile and Schedule at phone, tablet and desktop widths, with enlarged
   text, keyboard navigation and Midnight. Verify all quick-access destinations.
5. Reload the app and confirm the disclosed session-only demo reset.
